离线对每个相同状态计算
\[
\alpha_F(s)=\sum_f\min(p_F(f\mid h,a),q_F(f\mid h,a)),\qquad
j(s)=p_P(a\mid h)\alpha_F(s).
\]
按状态先算乘积再平均。Target 标签仅用于监督和评价；新草稿推理不读取标签。

在线完整 W1 轮次记为 N，首 P 实际接受次数为 N_P，P 已接受后首 F 的接受次数为 N_F。分别报告 N_P/N、N_F/N_P、N_F/N 及原始计数。残差样本与 bonus 样本只计入 emitted tokens；P 被拒绝的轮次中 F 未获实际验证，不能计为 F 拒绝。无可评价轮次时接受率记为缺失。验证调用与 token 量专指完整轮次的树验证，包含其待消费输入；另存全部 Target 调用及输入量，覆盖前缀、BOS 初始生成、K1 与恢复。每轮实际推进使用轮次生成长度，BOS 初始生成不纳入轮次均值。

## Paper 01：EAGLE-3

**论文信息**

Yuhui Li、Fangyun Wei、Chao Zhang、Hongyang Zhang，2025，*EAGLE-3: Scaling up Inference Acceleration of Large Language Models via Training-Time Test*。

- [原文 v3](https://arxiv.org/html/2503.01840v3)
- [官方源码](https://github.com/SafeAILab/EAGLE)，已读取版本 `cb7e0841fe0c206c6ed74a197ad5e2a1f13f5a2b`
- 原文材料：`docs/project/artifacts/pfspec_feature_states_20261105/EAGLE3.pdf` 及对应文本。

本次选择原因：当前轻量 Feature MLP 主要使用顶层状态，新增计算的收益有限。先评价额外读取已完成的浅层与中层表示，能否提高同一合法 Position 条件下的 Feature 分布重合。

**1. 可利用机制**

原文融合低、中、高层 Target 表示，连接实际抽样 token 的 embedding，经草稿预测下一个 token；直接 token 监督取消了精确拟合 Target feature 的约束。Training-Time Test 在训练中使用草稿自己的递归输出，以贴近多步推理。

抽象写为 \(z_t=W[h_t^{low};h_t^{mid};h_t^{high}]\)，\(q(x_{t+1})=\mathrm{softmax}(H D(z_t,e(x_t)))\)。这里仅表达信息流，省略原论文的多步结构；本项目未复现其完整 Transformer 草稿。

原文第 4.2 节 Table 2 在 MT-bench、Llama 3.1 8B 上报告：取消 feature 约束后平均接受长度由 4.05 增至 5.37；再加入多层融合后为 6.13。该数据支持其原任务中的机制，不作为 GaussianGPT 的加速依据。

官方 `eagle/traineagle3/cnets.py` 的 `fc` 将三层表示合并；训练循环将草稿输出用于下一步，并通过 token 输出头计算 soft-label CE。已对照原文 3.1、3.2、4.2 与这些源码路径。

本篇主要提取“多层已有 Target 状态融合”。当前 W1 本就直接预测 Feature token，未使用 feature MSE；单 Feature 草稿每轮重新读取真实 Target 状态，没有多步自递归，暂不加入 Training-Time Test。训练自然生成状态分布的单次细化另行报告。

**2. GaussianGPT 适配**

已提交 P_i、F_i，Target KV 已处理到 P_i，F_i 待消费。当前可用状态来自 P_i 的实际 Target 前向；Ranker 给出下一 Position 候选 a，草稿据此预测 F_{i+1}。真实 Target 的候选条件 Feature 分布须在消费 F_i、a 后才能获得，只能作为训练标签与评价依据。

现有 Target 共 24 blocks，选择零起始层号 5、11、23，每层 1,024 维。新增模型读取浅、中层现有表示，经 RMSNorm 与 2,048→256 映射加入旧顶层分支；保留已有 token 条件与残差 MLP，以及 Target 固定 Feature 输出权重。新增映射从零开始，初始行为与旧模型一致。

实现将三层状态连接为 3,072 维，作为 CUDA Graph 内部输出随重放更新；未把图创建时的 Python hook 值当成后续状态。训练和推理均只读取当时已计算的信息，没有读取未验证候选的未来状态。

合法 Position 排序与 Feature 范围保持。草稿仍提供实际 q_F，验证继续使用 min(1,p_F/q_F)；拒绝时从正部残差归一后抽样。提高 \(\alpha_F\) 可提高同历史 \(j\)，在线均值仍须实测。

主要成本为多层状态读取/连接、额外 2,048→256 计算与对应图输出。没有新增完整 Target 前向，也没有跨轮独立神经状态缓存。当前有限监督量与历史分布偏差仍可能限制收益。

**5. 机制分析**

多层已有 Target 表示提高了共同历史上的 Feature 重合度；同参数顶层对照提供了信息增量的直接证据。这与 EAGLE-3 关于多层信息有效的发现方向一致。本项目使用 Position 条件、每轮真实状态和单 Feature 提案，未声称完整复现 EAGLE-3 或引入其全部组件。

自然状态监督细化提升了正式在线补全的联合接受与推进，两个自然任务相对旧 W1 均有稳定联合收益。固定状态上 fusion 与 fusion_long 无可靠差异，不能将细化解释为所有历史上的统一改善。训练历史与在线访问状态的差异仍可能影响结果，当前未进一步分离其原因。

接受率提升已转化为两个任务的每轮推进提升，但没有形成两个任务均稳定的吞吐收益。独立 Draft 时延尚未可靠测量，额外状态读取和映射的成本留给下一阶段；本阶段不开展完整算子分析。

旧研究中的小规模在线开发及 VQ 输出保留在 `legacy_5090/`，不累加到本次正式样本数。开发验证状态参与过权重选择，其数字仅作开发依据；正式自然来源与状态单独统计。

**6. 研究结论**

本篇适配成立，`fusion_long` 同时达到两类自然任务的同历史重合度与在线联合接受提升，具备同参数信息对照、真实三维输出及可复用代码与权重。按正式评价前记录的规则，以 BOS、completion 等权的来源配对联合接受增量选交接候选：fusion_long 为 +4.631pp，fusion 为 +3.742pp，因此将 fusion_long 作为下一阶段接受率候选，fusion 同时保留。该选择不等于两个候选的总体差异已被显著区分。

本阶段达到用户定义的成功条件，首篇结束后停止文献扩展，不追加下一篇或继续训练。原 Position-only 与旧 W1 保留，不改生产默认模型；后续研究目标为减少提案额外计算及测量同后端 Position-only 的实际增量，须另行评价完整请求成本。

## Paper 2：Draft-OPD — 高接受率研究继续

### A. 文献信息

Haodi Lei 等，*Draft-OPD: On-Policy Distillation for Speculative Draft Models*，EMNLP 2026，26128–26141。[出版页](https://aclanthology.org/2026.emnlp-main.1139/)、[出版 PDF](https://aclanthology.org/2026.emnlp-main.1139.pdf)、[作者预印本](https://arxiv.org/abs/2605.29343)、[官方实现](https://github.com/Simplified-Reasoning/Draft-OPD)。源码版本为 `d6f0ec859321959785c65b59eb311fd25f042158`。

原论文针对长草稿块：已验证的最终续写遵循 Target 分布，丢失的拒绝草稿后缀却含有训练信号。§4.2 记录每块起点，重放同一草稿前缀并获取 Target 评分；接受部分用 forward KL，拒绝部分用 reverse KL，较晚拒绝位置降权。§5.2 的数据、KL 方向和起点消融支持这些机制。预印本 §6.1 报告仅首个拒绝 token 的平均接受长度为 5.94，完整方案为 5.95；这些数字来自 Qwen/DFlash，不能当作 GaussianGPT 结果。

### B. 可用机制与实际差异

原文公式（10）–（13）为两个分组均值：接受部分优化 `KL(p || q)`，拒绝部分优化 `KL(q || p)`，拒绝后缀权重为 `γ^(k-1)`。输入来自真实草稿起点及相同候选前缀，最终部署沿用原精确投机采样。

当前单 Feature W1 在每轮起点读取已提交历史的真实 Target 多层状态，再输入未消费的上一 Feature 和 Ranker 的 Position 候选。第一对中的 Feature 预测没有此前未提交 Feature 草稿，也没有递归草稿状态。因此，长草稿块的误差累积机制在此没有完整对应。

可观察的差异是轮起点选择：接受结果决定下一轮跨过多少 P/F 对，故真实轮起点的访问频率会依赖当前草稿。原训练沿预先生成的轨迹抽取位置，没有保留这些起点及原候选的接受/拒绝分类。服务器历史 `collect_pf_onpolicy_feature_data.py` 已收集过 Position 通过后的 Feature 分布，但没有将 Feature 拒绝结果分组用于双向 KL。该历史工作继续保留。

首候选只适配真实轮起点和接受/拒绝反馈，不宣称完整复现长块重放。单 Feature 情况下只有一个 Feature 判定位置，拒绝位置降权在分组归一化后为常数，没有独立贡献。

### C. GaussianGPT 接入与无损依据

`verification_feedback.py` 包裹已有 `propose`、树验证和 `decide` 调用，记录实际起点、输入状态、候选、验证分布、原 Feature 候选结果及生成量。它不额外抽取解码随机数、不改变 KV、不提交额外 token，也不新增 Target 前向。采样后剩余分布产生的 token 不计为草稿接受。

训练仅使用 Position 已通过的 Feature 状态，未到达 Feature 判定的分支单列保留。保留 `fusion_long` 的网络和多层输入，改变训练数据和分组目标。对照在完全相同反馈数据上续训原 CE+TV；需要时补 all-forward KL，以区分数据与双向损失的作用。

Top-p 使部分概率为零，两个方向的 KL 在支持不同的状态上可能无穷大。首候选仅在训练目标中使用 `pε=(1-ε)p+ε p_softmax`、`qε=(1-ε)q+ε q_softmax`，`ε=10^-6`，两种 softmax 均使用 temperature 0.9。真实接受、补采和评价仍采用原 temperature/top-p 0.9/0.9；训练辅助分布的变化如实记录。此处不把辅助 KL 当作真实单候选接受概率。

任意新草稿分布 q 仍通过原规则接受；接受贡献为 `min(p,q)`，拒绝后剩余贡献为 `(p-q)+`，相加为 p。Position、后续条件、EOS 和缓存提交都沿用已有实现。因此，草稿训练目标的变化不改变这项无损依据。实际验证先比较有无记录器的输出和动作，再开展训练、离线与在线评价。

## Paper 3：LK Losses — 直接接受概率目标

### A. 文献信息

论文比较两种 LK 目标与 KL、纯 TV、常数混合。Table 1 的随机采样 MLP：MT-Bench 的平均接受长度 KL 为 2.13，负 log 接受目标为 2.17，自适应混合为 2.19；HumanEval 分别为 2.16、2.19、2.62。这些是原文 LLM 数据，不作为 PFSpec 数字。作者声明公开训练数据与权重；当前尚未找到官方损失训练源码，公开仓库检索记录保留，实际实现据原公式编写。

### B. 可用机制

单 Feature 接受概率为 α=Σ min(p,q)，TV=1−α。§4.3 的目标为 L=−log α，梯度是 TV 梯度乘 1/α。它改变不同状态之间的更新比例，低重合状态得到更强的学习信号；目标均值 E[−log α] 与既有 E[CE+2TV] 的优化取舍不同。

§4.2 的另一目标为 λ KL(p||q)+(1−λ)TV，λ=exp(−η sg[α])；论文按草稿位置跨样本聚合 α，并让 λ 不接收梯度。默认 η=3。原文的常数混合消融没有得到相同优势。首轮先测试负 log 接受目标；如有依据，再在本篇的两次调整范围内测试自适应混合。

Appendix D 要求接受比值中的 p、q 与实际采样分布一致。原文已说明随机 Target 配合确定性 Draft 会改变接受概率的定义。当前实验继续从实际 q 抽取候选，沿用原精确接受及剩余概率采样。

### C. GaussianGPT 接入

## Paper 4：Towards Optimal Multi-draft Speculative Decoding

### A. 文献信息

Zhengmian Hu 等，*Towards Optimal Multi-draft Speculative Decoding*，2025-02 预印本，当前作者 v2 更新于 2026-11-02。[原文页面](https://arxiv.org/abs/2502.18779)、[v2 PDF](https://arxiv.org/pdf/2502.18779v2)。已读取 23 页版本的方法、候选构造、运输优化、§5/Theorem 8 证明、Appendix D 的完整采样式，以及温度和候选数消融。公开仓库按标题和 arXiv 编号检索尚未找到对应源码，当前据原文公式和伪代码实现，来源限制保留。

### B. 可用机制

原文 §5 确定性选择 q 概率最高的前 n−1 个候选 S，再从 q 在 S 之外的归一化分布 q′ 抽取一个随机候选 r。输出按 p 与 q′ 的精确单步耦合采样；集合接受概率为 α_set=p(S)+Σ min(p,q′)，它达到该候选集合分布的最优值。该最优性限定候选分布，未证明它在所有候选构造中最优。

接受 r 的概率是 min(1,p(r)/q′(r))，其余事件从归一化的 (p−q′)+ 完整抽取。若剩余概率输出属于 S，仍可使用已验证的对应分支。没有把 S 的候选分别套用原 q 的接受比值，没有舍弃集合之外的 Target 概率。

### C. GaussianGPT 接入

实际候选数不超过 q 的正概率类别数，保留一个随机剩余候选。集合命中包含随机候选接受和剩余概率命中确定性候选，两者分别保存。集合接受、单候选 overlap、候选数、Target 验证节点和每轮推进分别统计，不能将集合覆盖收益写成单 Feature 预测变强。

## Paper 5：Block Verification Accelerates Speculative Decoding

### A. 文献信息

Ziteng Sun、Uri Mendlovic、Yaniv Leviathan、Asaf Aharoni、Jae Hun Ro、Ahmad Beirami、Ananda Theertha Suresh，ICLR 2025，作者 v3 为 2025-04-10。[原文](https://arxiv.org/abs/2403.10444)、[完整 PDF](https://arxiv.org/pdf/2403.10444v3)。该篇来自 Paper 4 对多步验证方向的引用。已读取方法、算法 1–3、Theorem 1/2 及 Appendix B 的证明、Appendix A 的作者 Python 示意实现、温度/长度/模型/多候选对照。标题与编号的仓库检索未定位相关工程；附录示意代码含未定义的变量且原文明确不适合实际运行，按数学公式实现。

### B. 可用机制

逐个 token 验证在首个拒绝处结束。块验证令 u0=1，ui=min(ui−1 pi(xi)/qi(xi),1)，为各个前缀独立决定接受，取接受的最长前缀。最后位置接受率为 uγ；较早位置为 Ai/(Ai+1−ui)，其中 Ai=Σ(ui pi+1−qi+1)+。若止于该前缀，从归一化的 (ui pi+1−qi+1)+ 采样额外 token。原文证明整个输出序列保持 Target 分布，并在给定草稿路径信息、直接复用标准外层采样的条件下具有最优前缀接受能力。该结论不自动覆盖任意树构造。

### C. GaussianGPT 接入

主要适配联合验证首个 P/F 对：Position 提案为点分布，c=pP(a)，Feature 提案为 Paper 4 的实际剩余分布 q′。u1=c、u2=min(c pF(r)/q′(r),1)，首位置接受参数为 A/(A+1−c)，A=Σ(c pF−q′)+。首位置的接受决定与完整 P/F 对的接受决定均执行，取最长接受前缀。若只保留 P，则从完整的 (c pF−q′)+ 抽取 Feature。

额外确定性候选 S 继续预先验证；恢复采样的 Feature 落入 S 时复用其真实分支。组合后的 P/F 集合联合概率为 J=c pF(S)+Σmin(c pF,q′)，原方案为 G=c[pF(S)+Σmin(pF,q′)]，故共同历史 J≥G。单 Feature q 和集合构造保持原样。第二 Position 及后续 Feature 使用已选分支的完整 Target 条件，不声称整棵树全局最优。

### D. 代码与执行

## Paper 8：UniVer：多步与多候选的条件概率分配

### A. 文献信息

Yepeng Weng、Qiao Hu、Takehisa Yairi，arXiv:2605.04543v1，2026-05-06，19 页。[原文](https://arxiv.org/abs/2605.04543v1)、[PDF](https://arxiv.org/pdf/2605.04543v1)。已读取 Method、Eq. 3–10、Theorem 3–6、Appendix B 完整证明，以及不同模型、树深度、采样温度的消融。原文在特定 Top-(m-1)+一次剩余抽样条件下证明每层最优，未证明任意候选生成方式的全局最优。

公开仓库 `susan-zhu/univer` 的第 098d79572000b86010fe2a7b81494873641fe130 版包含复现实验，已读取树采样与验证分配源码。README 明确描述复现，作者身份与官方来源未确认；因此源码只辅助理解，算法依据采用原始论文。复现代码中对小概率采用 float32 epsilon 的处理未直接移植，本项目实际 Draft 存在小于该值的正概率。

### B. 可用机制

给定前缀有效接受概率 c、完整 Target 分布 p、去除确定候选的 Draft 分布 q′ 与其独立样本 u，样本接受质量为 min(1,c p(u)/q′(u))。其他 token 的质量按正部 c p-q′ 和拒绝质量 1-c 共同归一。候选依次按剩余未分配概率归一，所得有效概率向下一层传播。之后按子节点先于父节点的顺序作决策；叶节点后接 Target 样本，内部停止位置使用分配后的完整剩余分布。

局部平均输出质量恰好为 c p，局部拒绝平均质量为 1-c。候选生成保持原文的混合方式和条件独立要求时，按树的内部节点数归纳得到完整条件输出分布。不同 Feature 路径仍使用各自完整 Target 条件；不把第二 Feature 分布当作免费真值。

### C. GaussianGPT 接入

当前浅层 P/F/P 两个 Position 均为确定候选。96 组独立枚举确认 UniVer 在此结构上的首 P/F、三 token 接受及预期长度与已有 Block 相同，最大长度差 8.8818e-16，不计作新的增量实验。进一步 24 组更深结构包含 1632 棵完整随机候选树，枚举所有决策与全部条件输出，最大输出分布差 2.2204e-16；这是小词表概率证据，尚不证明真实 GPU 数值或 KV 行为。
